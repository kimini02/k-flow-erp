## API·모듈·정확한 실행 순서

새 API는 **`GET /api/organization/sites/{siteId}` 하나**다. `technical.site.AuthorizedSiteRead`와 `technical.web.SiteReadController`가 IAM Published Port와 Organization Published Port를 조립한다. Organization→IAM 역참조 또는 새 business module 없음.

1. `SynchronousAccessBoundary`가 REQUEST 외 dispatcher를 거부한다.
2. `SiteReadHttpBoundary`는 정확한 한 segment GET·raw URI 일치·직접 TLS·기존 exact Origin/Referer·중복 Cookie·미승인 forwarded header를 확인한다. 통과 표시를 요청 내에서만 유지하고 finally 제거한다.
3. 기존 `CredentialHttpBoundary`와 `AuthSecurityConfiguration`은 이 **검증된 경로**만 새 후보로 통과시킨다. GET 목록·다른 method·하위 경로·다른 API는 계속 deny. CORS 확대와 CSRF 제외 없음.
4. 기존 `RequestIdentityFilter`가 실제 Session 및 AN-03 Q를 확인한다. Q는 handler 전에 종료한다.
5. façade 본문에서 `requireCurrent(SITE_READ)` → 현재 principal → String UUID/query 검증 → `findSite(principal.companyId,id)` 순서로 진행한다. 권한 없음은 입력 파싱·대상 조회 전에 403이다.
6. 반환 ID/Company 및 기본 projection의 완전성을 검증한 뒤 `requireSiteRead(site.companyId)`를 수행한다. 같은 반환 객체를 정확히 **siteId/code/name/status**로 투영한다.
7. 성공·거부 모두 no-store. ETag 생성·Last-Modified·304 shortcut이 없으며 Q/정책 Allow를 cache하지 않는다.

정확한 matcher는 `SiteReadHttpBoundary.candidate`의 method=GET, REQUEST, 단일 비어 있지 않은 segment, `%`·`;`·역슬래시·추가 slash 제외, raw URI와 servlet path 일치 조건이다. UUID 타입의 MVC 자동 변환을 사용하지 않는다. 정규 UUID 문자열을 action 이후 파싱하며 버전 4 전용 제약을 추가하지 않는다. `%2F` 등 비정규 경로는 firewall/경로 경계에서 차단하며 데이터 반환이 없다.

Controller가 반환하는 별도 `SiteDetail`에는 companyId/version/Employee/Assignment/reason/timestamps가 없다. 오류는 고정 code/status/type만 포함하고 내부 예외·ID·SQL은 포함하지 않는다.

**Medium 1 — 구현 범위 CLOSED 후보:** 실제 기존 writer로 Employee/User/Credential과 reader/operator Role·grant를 준비한 **같은 PostgreSQL DB**에 새로운 embedded Tomcat TLS Spring Boot context를 시작했다. 실제 설정 두 개를 전달하고 Spring 생성 PolicyBindings=READY 및 Spring 관리 ActionAuthorizationService를 확인했다. 직접 new로 만든 서비스나 대체 정책 Bean이 아니다. owner spy는 관찰·장애·barrier 전용이며 권한 서비스와 Q는 원본이다. 실제 HTTPS에서 reader/operator=200, Role0/unmapped=403, revoke 후 새 Q=403, misconfigured/release mismatch/missing Role의 세 새 context는 403/owner 호출0을 확인했다. 운영 fleet release 일치·운영 Role/operator 준비 완료를 뜻하지 않는다.

## 실제 개발 실패와 수정

보존된 실행 로그의 순서를 따른다. 아래 fixture 오류를 운영 버그로 확대하지 않는다.

1. 최초 testCompile: MockEnvironment source의 Object 타입과 지원하지 않는 MockMvc builder dispatcher 메서드 사용. Map 명시 변환 및 request postprocessor로 수정(시험 코드 오류).
2. 선별 run1: 이미 예외를 던지도록 만든 Mockito stub을 `when`으로 재설정하면서 예외가 발생. `doThrow`로 수정(시험 코드 오류).
3. run2/3: 정상 HTTP가 403, 경쟁 barrier에 도달하지 못함. **실제 구현 연결 누락**: 기존 Credential 전역 필터가 새로운 Site 경로를 차단했다. exact Site transport 검사를 통과한 요청 표시만 해당 필터와 Security chain에 연결. Q/action 우회 없음.
4. run4: singleton 손상 주입을 public getCompany에 걸었으나 실제 findSite는 private company→store를 사용하므로 기대503 대신200. 실제 owner store 경계로 fixture 수정(기대 경로 오류).
5. run5: AOP proxy를 직접 spy해 Mockito unwrap 중 오류. 초기화 전 raw owner/store를 spy하도록 시험 BPP 수정(시험 인프라 오류).
6. run6: Session expiry_time만 바꾸면 실제 library의 last-access/max-inactive 검사가 만료를 판정하지 않아200. creation/last-access/expiry를 함께 과거로 설정해 실제 만료 fixture를 구성(시험 준비 오류). 기존 Session/Q Production 코드는 변경하지 않음.

잠재 위험과 제한: 현재 운영 TLS/Proxy 신뢰·fleet release·공유 limiter·capacity는 미완료다. read의 Q 이후 철회는 진행 중 응답을 소급 취소하지 않는다. 미래 민감 쓰기는 별도 최종 Guard가 필요하다. 이번 구현 검증에서 확인하지 못한 외부 환경 안전성을 PASS로 쓰지 않는다.

- **운영 공개 Gate OPEN**: AZ-03 M, 관리자 TOTP/MFA, Audit 동일 commit, 최초 operator, 운영 Role activation/release, 관리자 enable/SEALED, 마지막 관리자/복구, 운영 TLS/Ingress/Proxy, 공유 제한/capacity, 실제 배포·복원 및 기존 AN 운영 Gate.
- 기존 AN-02 익명 global/IP 예산 공정성 Medium 및 IAM-03 구 Role-only writer 혼합 배포 금지 유지. 테스트용 Role/User 준비는 운영 자동 seed가 아니다.

실제 최종 환경: Java 21.0.2; Spring Boot 4.1.1 / Spring Modulith 2.1.1; PostgreSQL 16.15, Testcontainers 2.0.5, Hibernate 7.4.5.Final.
