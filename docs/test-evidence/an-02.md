## 구현 경계와 실행 버전

Java 21 / Spring Boot 4.1.1 / Spring Modulith 2.1.1 / PostgreSQL 16.15 / Testcontainers 2.0.5 / Hibernate 7.4.5.Final. 실제 해결된 의존성은 **Spring Security 7.1.1, Spring Session JDBC 4.1.1**이다.

- P0: 정확한 네 경로의 HTTPS·Origin·method·body·budget 검사. 검증된 내부 marker만 기존 `CredentialHttpBoundary`를 통과한다. 기존 Enrollment consume와 기본 업무 차단은 보존했다.
- P1/P2: scalar snapshot → AN-01과 공유하는 `PasswordVerifier` + 기존 bounded `PasswordWorkBudget`. 해싱 중 Transaction/행 잠금 없음. dummy는 프로세스 최초 호출 때 무작위 hash를 예산 안에서 초기화한다. 초기화 비용 및 완전한 timing 균등은 보장하지 않는다.
- L: standalone writable READ COMMITTED. Employee `FOR SHARE` → User `FOR SHARE` → Credential `FOR SHARE`. 동일 PID/XID 및 실제 PostgreSQL SQL을 관찰했다. 기존 Reference/Assignment/AccountLink/RoleGrant/Credential Guard의 의미를 바꾸지 않았다.
- S/R: 공식 JDBC repository의 REQUIRES_NEW 저장 이후 **별도 DB 읽기**로 부모·필수 속성·principal index·만료 metadata를 확인한다. 작은 HTTP 응답은 filter finally 저장 종료까지 buffer한다. 저장 반환만으로 200을 보내지 않는다.
- Session: 공식 Session 4.1.1 PostgreSQL DDL의 V11, 두 테이블. JPA Session Entity 없음. `ON_SET_ATTRIBUTE`/`ON_SAVE`; auto-init `never`. V1~V10 원문 보존.
- Codec: 세 고정 shape(SecurityContext, CSRF, SESSION_AUTH_V2)만 JSON/BYTEA로 직렬화. 4096 bytes/depth 4/정확한 필드 집합/중복 key 거부. credentials/authorities/details 없음. 임의 class·JDK fallback·V1 자동 승격 없음.
- V2: User/Company ID, Credential version, User/Employee generation, authenticatedAt, absoluteExpiresAt, PASSWORD_ONLY만 저장. Employee ID·Role·소속 snapshot 없음. L의 generation을 S에서 최신화하지 않는다.
- 인증 absolute=idle=30일. absolute는 L의 최종 Instant부터 고정. framework idle/creationTime은 실제 system Instant를 사용하며 test sessionClock과 구분했다. 익명 absolute/idle는 명시 설정된 짧은 시험값을 사용한다.
- Cookie: `__Host-KFLOWSESSION`, Secure/HttpOnly/Lax/Path=/, Domain 없음. 인증 발급만 남은 초를 **내림**해 영속화. 익명 비영속, 삭제 0. 0초 이하 성공 발급 금지.
- 관측: 고정 카운터(로그인 성공/실패/일시 장애/요청 deadline, admission/거부/익명 생성, 저장 실패/손상 Session). 비밀/계정/IP를 metric label로 내보내지 않는다. 운영 수집기·경보 연결은 OPEN. framework Session/CSRF/JDBC bind 관련 민감 로그는 비활성화했다.

### 최소 설정 / 실행

기본 `kflow.auth.enabled=false`이므로 네 인증 경로도 503이다. 일반 업무 API는 계속 차단된다. enabled=true인 시험에는 아래 값을 모두 명시해야 하며 누락/잘못된 값이면 부팅 실패한다. **이 값들은 운영 권고가 아니다.** 실제 환경의 채택·측정 없이 활성화하지 않는다.

- `allowed-origins`(정확한 HTTPS origin), `window-seconds`, `ip-requests`, `key-attempts`, `map-capacity`
- `anonymous-global`, `anonymous-ip`, `anonymous-absolute-seconds`, `anonymous-idle-seconds`
- `deadline-seconds`, `max-session-rows`, `max-session-bytes`, `cleanup-grace-seconds`
- 실제 TLS는 별도 인증서 설정이 필요하다. 현재 app은 Forwarded/X-Forwarded-*를 신뢰하지 않고 거부한다. 운영 TLS termination/trusted ingress는 후속 Gate이다.

[실제 TLS 시험](../../backend/src/test/java/com/kflow/erp/iam/credentials/AuthenticationLiveIT.java)은 임시 인증서와 두 JVM을 만들고 제거한다. 공용 seed/고정 운영 계정/API는 없다. Chrome이 없는 환경이면 브라우저 하위 시험은 명시 NOT_RUN으로 기록하며 Maven의 skip 0으로 숨기지 않는다. 이번 실제 실행 여부는 아래 결과와 로그를 따른다.

## FR-C01/C02, FR-L01~03 판단

- **FR-C01**: 공식 JDBC가 attribute DataIntegrityViolationException 일부를 처리하는 경로가 있으므로 `save()` 정상 반환을 성공 증거로 사용하지 않는다. 실제 trigger/check 오류 및 누락 저장을 분리했다. 새 인증 S 전체 rollback 사례, 필수 metadata 생략 후 commit된 orphan 사례, logout 후 stale UPDATE0/부모 부재 사례는 서로 다르다. 실패 HTTP에 성공 Cookie/200/늦은 재저장 없음.
- **FR-C02**: S commit 후 Cookie writer 예외·남은 시간 subsecond/0은 503, 성공 Cookie 없음. DB orphan이 남은 것을 rollback이라고 하지 않는다. 자동 보상 삭제/재전달/재인증 없음. 후속 TTL/cleanup 대상이다.
- **FR-L01**: 실제 disable→enable/퇴사/RESET 및 L/S 간격을 관찰했다. V2의 L generation/credential version은 보존되며 S에서 현재값으로 변경하지 않는다. AN-02 session-info가 과거 인증 사실을 보여줄 수 있음도 테스트했다. 이것은 업무 접근 허가가 아니며 모든 업무 endpoint는 차단. AN-03 Q 없이는 구 자격 철회 완료가 아니다.
- **FR-L02**: 실제 ADMIN grant 후에도 PASSWORD_ONLY/빈 authorities. 관리자/업무 HTTP403. TOTP 구현 완료 주장은 없음.
- **FR-L03**: 익명 생성 전 node-total/IP 제한·유한 보관·실제 DB headroom/cleanup 실패 닫힘. COUNT headroom은 동시 원자 quota가 아니며, per-process map/restart/두 노드 한계는 공개했다. 운영 shared limiter·NAT·용량·경보 검증은 OPEN이다.

## 개발 중 실패와 수정 (실제 실행과 구분)

개발 로그는 실제 남아 있는 출력만 발췌한다. 과거 실패를 새로 재현하거나 추정하지 않았다.

1. Spring Modulith의 Clock 주입에 sessionClock이 추가되어 다중 후보 context 실패 → defaultCandidate=false + 명시 Qualifier. 비웹 Migration boot는 Session/HTTP 설정의 servlet 조건을 적용했다. 실제 통합 구성 수정이다.
2. SQL 증거의 첫 HR 잠금 직전에 XID를 할당하지 않아 trace assertion이 실패 → 관찰 위치를 SQL 전으로 변경. 업무 동작 수정 아님.
3. Spring Session lastAccess의 millisecond 저장을 test Instant nanosecond와 비교한 실패 → 기대 정밀도만 truncate(MILLIS). 실제 역행 사실을 삭제하지 않았다.
4. Session API에 없는 creationTime setter 시도/constructor 정리 누락/PSQLException AssertJ overload 모호성 → 컴파일 오류 수정. 시험 시간을 실제 framework system Instant와 분리했다.
5. 실제 자식 JVM 시험의 중복 CLI config와 browser fixture `/first` 분기 오류 → 시험 launcher/config/fixture 수정. 두 JVM 또는 브라우저 실패를 기능 성공으로 바꾸지 않았다.
6. 부정 저장/삭제·ACK/Cookie/오류 trigger는 **의도된 테스트 주입**이다. 실제 운영 장애 이력으로 기록하지 않는다.
7. 공식 JDBC 정상 반환과 실제 필수 attributes 저장 차이 때문에 좁은 검증 adapter를 구현했다. 라이브러리를 fork하거나 기본 SQL을 교체하지 않았다. 손상 principal/metadata 조회는 안전 폐기한다.
