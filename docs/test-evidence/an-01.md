## FR-A01 / FR-A02

- 늦은 E0 승인 뒤 E1이 생성되면 E1의 전체 컬럼·version·digest·시간 보존을 내부 비교한다. 새 E1 대상 승인만 교체 가능하다. EXPECT_NONE은 현재 pending이 발견되면 실패한다. old revoke flush 뒤/new INSERT 뒤 확정 실패는 각각 Root rollback한다.
- Bootstrap 발급/재발급에는 planId·canonical planDigest·environmentId·authorityScopeDigest가 Issue intent에 포함된다. 일반 Issue 승인 artifact로 Bootstrap Issue를 대신할 수 없다. 바인딩 대상과 최초 계획을 재검증하며 자동 reissue가 없다.
- `BootstrapPlanTest`의 독립 고정 JCS vector는 작은 고정 string schema의 key 순서/escape/UTF-8/digest를 확인한다. 계획과 실행 artifact bytes를 혼동하지 않는다. 같은 P의 새 승인도 최초 issuer/ref/record/pending을 덮지 않는다.

## 시간·Transaction·SQL 관찰

- 등록용 Clock: 2026-10-01, 경쟁용 Clock: 2026-10-11, 명령 referenceDate: Asia/Seoul. 실제 HR 등록 및 최초 Assignment를 commit한 뒤 경쟁한다.
- 독립 PostgreSQL Connection의 `pg_backend_pid()`/`pg_current_xact_id()` 및 `pg_blocking_pids`로 대기와 Root를 관찰한다. 테스트 전용 latch/spy는 실제 SQL 이후 멈추는 용도이며 production mutex/가짜 HR 저장을 추가하지 않는다.
- Credential의 Employee FOR SHARE와 grant의 Employee FOR SHARE 공존, Role SHARE→User SHARE 대기 및 후행 HR UPDATE 대기를 관찰한다. 별도 비키 version UPDATE 대조군으로 KEY SHARE와 혼동하지 않는다.
- `log_statement=all`, bind parameter 길이 0, `log_error_verbosity=terse`인 격리 PG에서 SQL template만 수집한다. 동일성 비교는 메모리에서 boolean으로 검증하고 password/token/hash/digest를 출력하지 않는다.
- 55P03/57014/40P01은 기술 실패로 구분하며 TOKEN_UNAVAILABLE로 오역하거나 자동 재시도하지 않는다. connection 종료는 서버 PID 소멸과 새 조회를 확인한 뒤 rollback 결과를 판정한다. afterCommit 예외 주입은 불명확 응답 대사 경계를 시험하며 실제 네트워크 ACK 유실 전수 시험이 아니다.

## 암호화·blocklist·자원

- 실제 resolved: Spring Boot 4.1.1 / Spring Security crypto 7.1.1 / Bouncy Castle 1.86 / Hibernate 7.4.5.Final / Testcontainers 2.0.5. 최종 실행 로그의 PostgreSQL·Java 값을 별도 기록한다.
- Argon2id ID `{kflow-argon2id-v1}` / memory 65536KiB, iterations3, parallelism1, salt16byte, output32byte. 이는 초기 측정 후보이며 운영 SLA가 아니다. PHC 값과 base64 canonical shape를 검사한 후 허용 profile만 검증한다. NFC는 encoder 밖에서 적용한다.
- `KFLOW_LOCAL_BLOCKLIST_2026_10_V1`: SecLists 고정 revision의 공개 NCSC common-password 자료에서 입력 길이 정책에 도달하는 329개 whole-value 항목을 local SHA-256 자료로 유지한다. 전체 출처·source/derived SHA-256·MIT 라이선스는 `backend/src/main/resources/credentials/blocklist-source.txt`, `SECLISTS-LICENSE.txt`에 있다. 짧은 corpus 항목은 입력 최소 길이로 먼저 거부된다. curated 일반/회사/정확 loginKey 문맥을 추가하며 최신 전체 유출 corpus 보장을 주장하지 않는다. 온라인 비밀번호 조회 없음.
- 기본 hash worker2/queue4/wait2000ms, 설정 상한 worker4/queue16/wait10000ms. 동기 hash가 끝나기 전 slot을 회수하지 않는다. 후보 메모리 비용은 기본 active Argon2 두 개만으로 약128MiB + JVM/라이브러리 overhead이며 운영 측정치가 아니다.
- consume 후보 한도: 단일 process global64/min, source10/min, 최대 source128. 실제 공유 IP·다중 instance·장비 운영 정책은 OPEN. TLS/origin/size/용량 검증이 인증 없는 관리자 API를 허용하지 않는다.

## 실제 운영 Gate / 보장하지 않는 것

- 기본 `OperatingApproval`은 모든 발급·취소·Bootstrap 운영 승인을 거부한다. test-only registry는 실제 서명/identity/2인 승인 플랫폼의 증거가 아니다. 운영 adapter/job 제어가 연결되기 전 실행 불가.
- allowed-origins 기본 비어 있음: consume endpoint 503. 테스트는 실제 random-port 서버의 기본폐쇄와 MockMvc의 `secure=true` TLS ingress fixture를 구분한다. 실제 TLS 인증서·ingress·access/body/trace 로그·신뢰 proxy·외부 전달 검증은 OPEN. 현재 forwarded headers는 신뢰하지 않고 거부한다.
- 일반 HTTP 업무 경로는 403, 기술 OpenAPI/Swagger GET과 정확 consume POST만 구분한다. Role 이름이나 ADMIN code, Credential 존재, PREPARED는 접근 허가가 아니다.
- application 로그는 Hibernate 오류 DETAIL·bind/extract를 제한하고 새 Credential 오류는 SQLSTATE만 보존한다. local Compose도 parameter/DETAIL을 제한한다. 운영 DB/trace/ingress 설정 override 및 권한·백업은 별도 gate다. JVM의 모든 String 완전 삭제를 보장하지 않는다.
- raw SQL/savepoint 우회 전면 방지, 전역 exactly-once/원 요청 귀속, 실제 네트워크 commit-window 장애 전수 검증을 주장하지 않는다.

## 개발 중 실제 발견·수정

- 테스트 컴파일: JUnit/JPA `Timeout` 이름 충돌, Java Unicode escape의 줄바꿈 전처리를 수정했다. 업무 규칙 변경이 아니다.
- 첫 통합 실행: 기존 RESET fixture의 consumed Enrollment 개수, 준비 단계 Guard 호출 횟수, Spring 예외 변환 기대값 오류를 수정했다. 저장 원자성 assertion을 제거하지 않았다.
- 구현 검토: DB 오류 원문·DETAIL이 민감 값을 노출할 수 있어 SQLSTATE만 보존하는 `CredentialStorageFailure`와 로그 경계를 추가했다. TOKEN_UNAVAILABLE와 기술 장애는 구분한다.
- 구현 검토: Bootstrap Enrollment 승인 intent의 계획 scope 누락을 보완했다. planDigest/environment/authorityScopeDigest와 정확 target/version에 결합한다.
- CHECK 독립 시험을 위한 V10 식 재배열 시도는 자동 승인 검토에서 무결성 약화 우려로 거절되어 적용하지 않았다. 원래 V10 제약을 유지하며 purpose/base를 동시에 위반하는 입력은 SQLSTATE와 양쪽 제약 정의를 확인하고 최초 제약명을 고정하지 않는다.
- 첫 전체 verify는 Surefire 92 성공, Failsafe 679 실행 중 실패 4/오류 1이었다. 부정 Transaction 관찰 helper가 Guard 전에 정상 연결을 assert한 시험 오류 4건과, 기존 IAM-03의 중복 grant를 성공 no-op으로 기대한 오류 1건을 수정했다. 실제 계약은 `GRANT_ID_CONFLICT` 후 정확한 grant 사실 조회이며 기존 IAM-03 코드는 변경하지 않았다.
- 공개 blocklist 취득 시 Python CA 오류와 이전 파일명의 404가 있었으며 TLS 검증을 끄지 않고 GitHub CLI 및 확인된 현재 파일명으로 수집했다.
