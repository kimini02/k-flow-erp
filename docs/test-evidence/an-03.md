## 구현과 보장 경계

경로 기준은 `backend/src/main/java/com/kflow/erp/`다.

- `iam/application/authentication/RequestIdentityResolver`: ambient TX/동기화와 caller-bound EntityManager/DataSource 를 시작 전에 거부한다. 전용 TransactionTemplate 의 read-only RR Q 는 primary 의 plain SELECT 만 수행한다. 기존 writable RC Root 와 REQUIRES_NEW 정책을 변경하지 않는다.
- `iam/infrastructure/authentication/JpaAccessContextStore`: bound 실제 JDBC 연결의 autoCommit=false, readOnly=true, isolation=RR 및 PostgreSQL `transaction_isolation`, `transaction_read_only`, `pg_is_in_recovery()=false`를 확인한다. 최초 계약 SELECT 의 `pg_current_snapshot()` 자체가 Q 의 첫 snapshot 을 획득한다. 이후 IAM User/Credential metadata 와 Role/grant 두 data SELECT 를 실행한다. Credential hash 는 선택하지 않는다.
- `hr/api/EmployeeAccessFactsQueries` → `EmployeeAccessFactsService` → `JpaHrAccessStore`: MANDATORY 로 동일 bound connection 에 참여하고 물리 RR/primary 를 다시 확인한다. Employee + 날짜별 Assignment 후보를 한 SQL scalar projection 으로 읽는다. 현재 후보 1 개·회사·직원·ID·기간·입사 경계를 검증하며 LIMIT 1/Entity/lazy/flush/clear/detach 를 사용하지 않는다. HR→IAM 의존이 없다.
- Q 는 3 개 **data SELECT**와 IAM/HR 의 2 개 **계약 SELECT**를 수행한다. 실제 transaction·driver·Session I/O 를 포함한 요청 전체 SQL 을 3 개라고 주장하지 않는다. 모든 statement timeout 은 5 초, Q template timeout 도 5 초이다. 전체 HTTP admission deadline 과 물리 connection 대기 시간은 기존 설정의 별도 경계이다.
- Q 가 정상 commit 한 뒤에만 불변 `iam/api/RequestPrincipal`을 반환한다. `PrincipalAccessQueries.requireCurrent()`는 HTTP 요청·현재 스레드·REQUEST dispatcher 에 바인딩된 DTO 만 제공하며 세션에 저장하지 않는다. query/body 의 actorId, 저장된 authorities, Role code 로 actor/권한을 만들지 않는다. expiresAt 을 handler 직전에 재검사한다.
- RequestIdentityFilter 는 SessionValidity/CSRF 뒤, AuthorizationFilter 전에 실행된다. 기존 outer AuthHttpBoundary/CredentialHttpBoundary 의 정확한 method·Origin·budget·업무 default deny 를 유지한다. 현재 외부에서 Q 가 적용되는 endpoint 는 `/api/auth/session`이고 응답 필드는 기존 4 개만 유지한다. `/csrf`, `/login`, `/logout` 및 기존 consume/docs 예외는 확대하지 않았다. 허용되지 않은 업무 URL 은 outer default deny 에서 먼저 403 이므로 Q 를 강제로 실행하지 않는다.
- 모든 dispatcher 에 등록한 `SynchronousAccessBoundary`는 Session persistence 밖에서 FORWARD/INCLUDE/ERROR/ASYNC 를 sanitized403 으로 차단한다. asyncSupported=false. 성공/거부/예외 모두 request principal 을 finally 에서 제거한다. 실제 업무 API 는 개방하지 않았다.
- 알려진 신원의 DB/정합성/Q 실패는 generic503, 과거/무효 인증은 401, CSRF·업무 default deny 는 403 이다. 일시적 Q 실패를 이유로 Session 을 파괴하거나 과거 actor 로 fallback 하지 않는다. 보안상 무효인 Session 행이 남아 있어도 Q 에서 접근을 거부한다.
- User/Employee generation writer·Credential RESET·L/S·V2 codec·30 일 absolute/idle·current logout·Argon budget·기존 Session 검증은 재사용한다. 기존 `LoginConcurrencyIT`의 late-S `/session` 기대값만 승인된 AN-03 동작에 따라 200→401 로 강화했다. 원래 stamp/DB/업무 403 assertion 을 보존했다.

### 실제 환경 / 관측

최종 로컬 Java 21, CI Java 21; Spring Boot 4.1.1 / Modulith 2.1.1 / Security 7.1.1 / Session JDBC 4.1.1 / Hibernate 7.4.5.Final / Testcontainers 2.0.5 / PostgreSQL 16.15. 초기 개발 실행 일부는 Java 22.0.2 로 수행했으며 Java 21 최종 실행과 구분한다.

고정 cardinality 카운터(resolved/denied/unavailable/elapsedNanos)를 제공한다. 테스트가 Q SQL·pool 해제와 **4 workers × 10 회 / Role 0 개** 표본 지연·관측 active connection 을 로그에 기록한다. 샘플의 median/p95·관측 peak 는 운영 SLO, 최대 pool 사용량, 용량 보장이 아니다. 실제 운영 수집기·connection wait dashboard·부하 한도는 OPEN 이다.

## 판별력 보강 / 실제 격리 환경

- §11.7: Q 의 첫 계약 SELECT 가 snapshot 을 확보한 **후** barrier 를 열어 독립 writer 가 실제 전보와 grant 를 commit 한다. Q1 은 옛 Assignment/빈 grant, Q2 는 새 Assignment/정확한 새 grantId 를 반환한다. IAM/HR 가 같은 Connection·PID·snapshot·primary RR 인지를 직접 검사한다. plain SELECT 의 `pg_blocking_pids`=0 을 확인한다. read-only/PID 하나만으로 PASS 하지 않는다. 실제 replica 서버를 배치하지는 않았으며 primary 확인과 잘못된 DataSource 거부를 검증했다.
- §11.8: test-only protected controller 의 직접 URL/5 개 method 는 실제 전체 filter chain 에서 403, 호출 0 이다. non-REQUEST dispatcher 는 persistence 이전에 거부한다. `/session` handler 에서는 request principal 이 보이지만 Q/TX 는 종료되어 있고, 다른 thread·다음 요청에는 principal 이 없다. 현재 production SecurityFilterChain 은 하나이며 가상의 다중 chain 을 시험했다고 하지 않는다.
- T34: `An03ColdCutover`는 **test helper**다. Git 에 고정된 AN-02 기준 commit 을 임시 폴더로 archive 하고 offline package 하여 실제 이전 jar 를 별도 보관·실행한다. 현재 build 에서 이미 resolve 한 동일 의존성을 재사용한다. 이전 jar 에 Q class 가 없음을 확인한다. 시험에서 승인한 현재 jar SHA256·모든 old PID 종료·Session 0 을 확인한 뒤에만 새 기동한다. 구 Session bytes/구 artifact/backup 은 분리 보관하고 시험 종료 후 제거한다. 전체 Git 이력이 필요하여 CI checkout 만 fetch-depth 0 으로 변경했다. 이것은 실운영 배포 방어를 새로 구현한 것이 아니다.
- 격리 복원은 Testcontainers DB 만 사용한다. 실제 pg_dump/pg_restore 가 generation 을 과거 0 으로 되돌리고 정확한 Session 집합을 복원하는 것을 확인한다. 모든 자식 JVM 이 종료된 상태에서 Session/attributes 를 purge 하고 업무 행수를 보존한다. 구 Cookie 로 재시작 요청은 401 이다. 운영 DB/개발 공유 DB 는 수정하지 않는다.
- 실제 L/S HTTP barrier·writer flush/rollback 주입은 test-only spy 다. password/hash/Session ID/CSRF·HR reason 을 로그에 내보내지 않으며 PG SQL bind 값은 기존 테스트 설정에서 비활성화한다. wrapper/beforeCommit failure 를 실제 네트워크 ACK 유실 전수 시험으로 확대하지 않는다.

## 개발 중 실제 문제와 수정

1. 초기 Q 의 `EntityManager.isJoinedToTransaction()`은 실제 연결이 read-only RR·active 여도 false 였다. 물리 Connection·transaction binding·server 상태로 검증하도록 수정했다.
2. 선적재 EntityManager 를 Q 에 참여시키고 거부하면 JpaTransactionManager rollback 이 caller 의 관리 객체를 clear 했다. **Q 시작 전에 caller-bound EM/DataSource 를 거부**하여 간섭을 막았다. 지원하지 않는 ambient context 를 suspend/REQUIRES_NEW 로 숨기지 않는다.
3. AN-02 late-S `/session`의 200 기대값은 이번 승인된 Q 계약에 따라 401 로 강화했다. unauth 업무 URL 의 기존 403 을 401 로 잘못 바꿨던 개발 중 기대값은 원래 403 으로 복구했다. 보장 약화가 아니다.
4. 보강 실행의 잘못된 `ArchitectureTest` 선택자는 실제 `LayerArchitectureTest`/`ModuleArchitectureTest`로 수정했다. Production 버그가 아니다.
5. 구 artifact 시험의 `git archive`가 backend 하위에서 다시 backend 경로를 찾던 fixture 오류를 repo root 실행으로 고쳤다. Production 버그가 아니다.

실패·수정 사항은 실제 [개발 로그](an-03-development-run.txt)에 따른다. 잠재 위험을 재현된 취약점으로 기록하지 않는다.
