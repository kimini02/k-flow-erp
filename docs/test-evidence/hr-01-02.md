## 3. 구현 구조 / Trade-off

- `hr.api`: EmployeeIdentityQueries / EmployeeAssignmentQueries와 불변 사실 DTO. 계정 생성 허가·권한 판정 아님.
- `hr.application.EmployeeRegistrationService`: ambient Transaction 거부, standalone writable READ COMMITTED Root, 단일 Clock 캡처, Guard→Employee flush→Assignment flush→실제 commit. 자동 retry/보상 없음.
- `hr.application.EmployeeQueryService`: 직원 사실, 현재·asOf 소속, 내부 직원·이력 pagination. 상세 날짜 조회의 최소 integrity 검사는 전체 timeline 검사를 대신하지 않는다.
- `hr.infrastructure.JpaHrStore`: 쓰기는 JPA, 날짜 조회는 기존 EntityManager Connection에서 한 JDBC scalar SELECT. 관리 객체/flush mode를 clear/detach/변경하지 않는다. HR SQL은 HR 테이블만 조회한다.
- 오류 변환은 Root 실제 완료 밖에서 SQLSTATE+제약 이름을 함께 확인. PostgreSQL 드라이버의 구조화된 metadata가 필요해 기존 의존성의 runtime scope를 compile scope로 바꿨다. 새 라이브러리/Framework를 추가하지 않았다.
- V4: Organization 소유 `(company_id,id)` UNIQUE 3개. V5: HR 테이블·composite FK·btree_gist·NOT DEFERRABLE EXCLUDE. V1/V2/V3 원문 불변. 운영의 extension 설치 권한 부족은 배포 실패이며 App-only로 약화하지 않는다.
- 모든 QA용 이력 수정/제약 일시 해제/장애 주입은 테스트 범위다. production 전보/퇴사 API나 HR seed가 아니다.

## 6. 실제 발견한 문제와 수정

1. 초기 컴파일 실패: 기존 CompanyReference accessor를 `id()`로 잘못 호출했다. 실제 계약인 `companyId()`로 수정했다. 승인 정책 변경 없음.
2. 첫 부분 테스트 39개 중 13개 실패: 테스트 관측기가 대소문자 구분 `LIKE`로 대문자 `FOR SHARE/UPDATE`를 놓쳤고, Spring Repository의 `InvalidDataAccessApiUsageException` 래핑을 테스트가 원본 IllegalStateException으로 기대했다. 관측을 `ILIKE`, 예외 assertion을 실제 wrapper+root cause로 수정했다. 잠금/원복 assertion을 제거하지 않았다. 이 부분은 **테스트 관측·기대값 수정**이다.
3. 두 번째 부분 테스트 50개 중 1개 실패: 실제 commit 단계의 지정 23505가 Hibernate ConstraintViolationException 없이 PostgreSQL driver cause로 전달되어 업무 충돌로 변환되지 않았다. **실제 구현 버그**다. 구조화된 PSQLException metadata를 추가로 읽되 SQLSTATE+constraint 두 값 일치 조건은 유지했다. commit trigger 부정 테스트가 통과하고 pair0을 확인했다.
4. 이후 전체 검증 200 PASS, 추가 경계·휴직 조회 검증을 포함한 최종 전체 203 PASS. 최종 로그가 현재 파일 해시와 연결된다.

## 7. 남은 보장 범위와 후속

- 이 제출은 HR-01/02만이다. HR-03/04/IAM/Item, 실제 전보·퇴사·휴직·복직·계정 생성·인증/인가·Frontend·외부 관리 API는 미구현.
- O3의 test-only consumer를 실제 HR 저장까지 연결했지만 후속 인사발령 경쟁까지 완료했다는 뜻은 아니다.
- after-commit wrapper는 실제 DB commit 뒤 응답 손실을 모사한다. 실제 네트워크 ACK 유실, 운영 raw SQL/savepoint 우회 전수 방지, commit-window 네트워크 장애 전수 검증은 주장하지 않는다.
- 직접 SQL의 공백/ACTIVE 우회, 페이지 요청 간 snapshot, 현재 Organization 표시명의 과거 snapshot 미보장.
- 최초 소속/사번 오입력 정정, 초기 이관·재입사·예약은 후속 정책이다. 기존 직원을 오늘 신규 입사자로 위장 등록하는 기능/seed 없음.
- 전체 감사·행위자·권한·개인정보·Payroll까지 완료한 것이 아니다. PM3 리뷰를 기다리며 다음 Slice는 자동 시작하지 않는다.
