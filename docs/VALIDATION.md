3. 회수는 기안자만 가능.
4. 확정 문서 수정 방지.
5. 초과 지급 배분 실패 시 원 잔액 보존.
6. 차대변 불균형 거부, 역분개 원 전표 보존, 중복 역분개 거부.
7. 마감 기간 전기 거부.
8. 창고 이동 수량 보존, 부족재고 처리 시 전체 롤백.
9. 검색·상태·기간·pagination 조합.
10. 초기 전표 차대변 균형 및 모든 관련 문서 링크의 대상 존재.

## 브라우저 테스트

`npm run test:e2e` — 8개 시나리오. 53개 하위 메뉴 경로 + 대시보드 = 54개 경로 화면.

- 전체 하위 메뉴의 한글 제목/실데이터·재무제표 표시, JavaScript pageerror 없음.
- 대시보드와 Assistant 우측 패널 캡처.
- 검색/빈 결과/초기화/pagination/상세 Drawer/발주 등록/새로고침 후 저장 유지.
- 사용자 전환 후 현재 결재자 승인, 다음 결재자 이동.
- AI는 확인 전 미생성, 취소 시 미생성, 명시적 확인 후 1건 생성, 생성 문서 이동.
- Mock 통신 실패 상태 표시, 오류 해제 후 재시도 복구.
- 390px 모바일에서 메뉴와 목록, 페이지 전체 가로 넘침 없음.
- 지급 Modal의 미결제 배분, 저장 후 전표 링크 확인.

브라우저 테스트에서 발견한 실패는 재무제표를 목록 테이블로 가정한 선택자, Mantine Select의 input/listbox 중복 이름, 비활성 탭에도 유지되는 문서 링크 선택자의 중복이었다. 화면 유형·역할·활성 요소에 맞게 테스트를 수정했다.
