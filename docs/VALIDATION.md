## 브라우저 테스트

`npm run test:e2e` — 8개 시나리오. 53개 하위 메뉴 경로 + 대시보드 = 54개 경로 화면.

- 전체 하위 메뉴의 한글 제목/실데이터·재무제표 표시, JavaScript pageerror 없음.
- 대시보드와 Assistant 우측 패널 캡처.
- 검색/빈 결과/초기화/pagination/상세 Drawer/발주 등록/새로고침 후 저장 유지.
- 사용자 전환 후 현재 결재자 승인, 다음 결재자 이동.
- AI는 확인 전 미생성, 취소 시 미생성, 명시적 확인 후 1건 생성, 생성 문서 이동.
- Mock 통신 실패 상태 표시, 오류 해제 후 재시도 복구.
- 390px 모바일에서 메뉴와 목록, 페이지 전체 가로 넘침 없음.
- 지급 Modal의 미결제 배분, 저장 후 전표 링크 확인.

브라우저 테스트에서 발견한 실패는 재무제표를 목록 테이블로 가정한 선택자, Mantine Select의 input/listbox 중복 이름, 비활성 탭에도 유지되는 문서 링크 선택자의 중복이었다. 화면 유형·역할·활성 요소에 맞게 테스트를 수정했다.

## 색상 수정 (2026-09-29)

사용자 참고 이미지에 맞춰 포인트를 선명한 초록색(#008000), 사이드바를 차콜(#24282b)로 변경했다. 선택 메뉴, 주요 버튼, KPI, 차트와 관련 강조색에 반영했다. TypeScript/production build 통과. 대시보드·상세창·결재·모바일 브라우저 검증 4개를 재실행하고 캡처를 갱신했다.

## 디자인 개편 (2026-10-08)

`design/erp-ui-refresh` 브랜치에서 화면 디자인을 개편했다(커밋 64c8eef 기준선 이후). 이전 색상 수정(차콜·초록)과 보고서의 초록 농도 매핑은 이 개편으로 대체되었다.

- 디자인 기준: 흰 작업 면·옅은 회색 메뉴·파란 강조색 1개, Pretendard Variable(CDN), 글자 11px 이상, 표 행 36px.
- 메뉴: 모듈 레일 + 묶음별 하위 메뉴, 상단바에 회사·현재 위치, 현재 화면 `aria-current`, 본문 건너뛰기 링크.
- 목록: 한 줄 요약, 금액 오른쪽 정렬, 헤더·첫 열 고정, 페이지 크기 선택, 문서번호 버튼.
- 현황 보기: 재고현황, 채권·채무 연령분석, 수불부, BOM 구성표, 총계정원장 누적 잔액, 결재함 처리 대기.
- 재무제표 양식, 분석 보고서, 대시보드 재구성. 상세 Drawer(목록 유지, `?path=` 경로, Escape 한 단계 뒤로, 연결 문서 기준 흐름). 품목행 문서는 전용 작성 화면, 기준정보는 오른쪽 패널.
- 시드 데이터: 수불은 확정 원천 문서에서 생성하고 기초재고를 역산(누계 = 현재고). BOM은 품목별 사용 버전 1개·자기 투입 없음. 9월 전표는 업무 순서로 재구성(잔액 비음수, 자산 = 부채 + 자본).

검증: TypeScript 통과, 업무 테스트 31개(시드 정합성 3개 추가) 통과, 브라우저 시나리오 13개 통과, 54개 경로 렌더링·현재 메뉴 표시·pageerror 없음 확인. 브라우저 시나리오 변경은 목록 기본 20건, 새 모바일 메뉴 조작, 재고현황·매입채무의 기본 현황 보기 반영이다. `docs/screenshots/`의 캡처를 새 화면으로 갱신했다. 접근성은 키보드 이동·포커스 복귀·대비 등 일부만 확인했으며 전체 접근성 감사를 한 것은 아니다.

## Mock 시드·키보드 정리 (2026-10-08 ~ 10-11)

코드 검토에서 나온 지적을 고쳤다(커밋 39a0936, dfc2e9b). 테스트를 맞추려고 숫자를 고치지 않고, 수불을 만드는 규칙과 확정 원천 문서 사이에서 빠진 부분을 찾아 고쳤다.

- 키보드: 수정 패널·대화상자·Assistant에서 누른 Escape와 화살표는 그 창만 처리한다. 뒤의 상세나 목록은 바뀌지 않는다. 등록 패널을 닫으면 `?new=1`이 지워져 새로고침해도 다시 열리지 않는다.
- 수불: 처음 6건만 반영하던 자재출고·생산입고를 확정 문서 전체로 넓혔다. 실제 문서가 없는 재고조정 수불을 지웠다. 확정된 창고이동(출발 창고 출고 + 도착 창고 입고)과 재고조정도 수불에 반영했다. 창고이동은 즉시 이동으로 기록했으며 이동 모델(DR-21)은 미정으로 둔다.
- 품목 역할(DR-01): K-100만 생산한다. S-200·M-50은 BOM·작업지시가 없는 재판매 상품(품목 유형 "상품")이다. 구매·결재 시드는 K-100을 사지 않고, 판매 시드는 K-100·S-200·M-50만 판다. 다단계 BOM 정책(DR-04/18)은 정하지 않았다.

검증: TypeScript 통과, 업무 테스트 34개 통과(확정 문서의 수불 반영, 재고조정 수불의 원천 문서, DR-01 생산·판매·구매 품목을 검사하는 테스트 추가), 브라우저 시나리오 13개 통과, 54개 경로 확인. 시드 기준 수불 149줄에서 빠진 확정 창고이동·재고조정 0건, 음수 재고 0건, 품목·창고 21개 조합 모두 수불 누계 = 현재고. 이동·조정이 반영되면서 대시보드의 안전재고 미달이 5건이 되었고, `docs/screenshots/`의 캡처를 다시 찍었다(결재 화면은 바뀐 내용 없음).
